# Independent debugger review

The required Debugger responsibility was performed in a second role wave after the Property Manager implementation because the task has a four-agent concurrency limit. This review inspected other modules independently, exercised actual React components in an isolated browser, and used synthetic sessions/transport responses. No environment credentials, production accounts, database records, real provider authorizations or deployments were used.

## Source and boundary review

- CEO aggregation delegates farm financial values to existing authoritative `getFarmFinance`, rather than rebuilding financial formulas. It reads complete rows independently of UI list pagination. Independent business-query failures return unavailable sections while other sections remain available. It fetches inventory reversals before filtering active mortality by reporting date, so a later reversal can correctly remove an earlier mortality event.
- Property financial aggregation separates ISO currencies and treats maintenance work cost as recorded information, not another paid expense. Current vacancies/stock/work queues are distinguished from period cash ledgers. Property API validates real dates and strictly whitelists fields; database enforces parent currency, rent period, occupancy and tenancy invariants. Actual API checks load the real session guard.
- Content publication inputs convert browser-local date/time into timestamp offsets before storage; date-only ledgers remain date-only. Unavailable performance measurements remain NULL. CEO audiences use account snapshots, not follower sums across post/date records. A newer incomplete snapshot may legitimately show an unavailable metric; the implementation does not invent a value.
- Farm reports remain separate from day-open/close state. Narrative report observations do not generate financial or stock movements. New dated writes use the existing farm closure routine; decision/review metadata can be added after operational closure without changing accounting.
- New write actors derive from verified server sessions. Client-supplied actor fields are rejected. Database RPCs additionally recheck the active domain role; direct new-table writes are revoked. Domain history retains immutable original and saved values.
- Instagram state is signed, actor-bound and cookie-matched; authorization/synchronization require an active CEO. Tokens use authenticated randomized encryption and guarded token routines. Official transport has a bounded timeout, and generic provider/database failures do not expose token text. Real provider behavior remains unverified until an authorized account and developer configuration are supplied.

## Social completeness and external gates

At the first review, only Instagram OAuth and follower synchronization were prepared; Facebook and TikTok were manual-only. This gap was reported and the content owner subsequently prepared conditional Facebook/TikTok OAuth, guarded encrypted persistence, disconnect and follower synchronization. Independent source review confirms platform-bound state, exact configured Facebook Page selection, provider pagination host validation, TikTok success-envelope handling, account checks and refresh-token rotation. The owner's additional isolated provider suite reports 59 actual handler checks. Missing developer approval, credentials and account consent still block live authorization.

TikTok's official [Get User Info](https://developers.tiktok.com/docs/en/tiktok-api-v2-get-user-info) documentation (updated August 4, 2026) documents follower statistics under the `user.info.stats` scope. Its [Display API setup](https://developers.tiktok.com/docs/en/display-api-get-started) requires Login Kit/API approval and account consent. This proves a conditional official path exists; it does not prove Bimbo's account/app is currently approved or promise complete reach analytics. TikTok success responses include an `error` object with code `ok`, so the Instagram helper's generic truthy-`error` rejection cannot be reused unchanged.

Direct official Facebook Pages documentation returned HTTP 429/unavailable during this independent review; the owner used a Meta-owned API collection, documented in the social guide. Third-party articles were not used as technical authority. Current scopes, fields, metrics and application access must be verified with an approved account before a real connection is claimed. No paid aggregator or billing upgrade was requested or used.

Automatic imports currently support followers only. Reach/impressions/engagements remain explicitly measured manual entries. TikTok refresh is implemented while a valid access token is near expiry; after access expiry, the guarded token-read routine refuses it and the UI requires reauthorization. Refresh after access expiry is not claimed.

Official sync currently assigns an account observation date using the shared Lagos reporting date. The business reporting timezone for BossBimbz content should be recorded at release; do not silently claim an account-local provider reporting period. Manual date entries remain the user's explicit dates.

## Evidence and limits

Property evidence at this review: 50 actual API checks with real session guard; 36 styled actual React/browser checks at 390/768/1440 pixels; targeted ESLint and project TypeScript verification. Browser screenshots are private temporary artifacts under `bossbimbz-property-ui-yFtFRF`, not application fixtures.

The independent lost-response regression originally reproduced three failing conditions and confirmed that the pre-fix farm identical-payload retry already avoided duplication. After the content/farm fixes it passes **11 actual React/browser checks**, including frozen payload restoration, stable UUID, one committed financial sale, one farm request, and genuine actor/timestamp rendering. Full regression, build, production catalog comparison and final branch push are root release evidence, not inferred from this review.

Synthetic single-session database and browser tests do not establish real provider permissions, hosted multi-session lock behavior, DNS/subdomain configuration, developer-app approval, production migration installation or a successful deployment. Those gates remain explicit.
