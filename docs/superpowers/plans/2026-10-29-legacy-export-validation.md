# Restricted manager history export

Scope: the approved plan's Task 7. The two server-authorised accounts are Farm Manager and Emmanuel Adeolu. The CEO may export either account, including a suspended target; an active eligible manager may export their own history. Other staff and future accounts have no export button or download permission. No editable profile flag enables it.

One read-only, consistent PostgreSQL snapshot includes every attributable period, original source rows, related administrative corrections/voids, dated physical activity, custody, pending decisions and attributable retry receipts. Shared asset acceptance is separate from personal transactions. Bimbo's old transfers without a recipient remain unallocated and cannot establish personal opening cash or debt. No source values or account fields are updated by export. Empty business sheets stay empty; genuine operating-period metadata is retained.

The workbook contains a readable Summary and distinct source sheets. Original numeric values and nested JSON remain exact text; the original row JSON is also retained. Safe monetary number columns aid normal Excel work, while a blank numeric companion is explicitly explained as unrepresentable precision, not zero. Long Unicode text is split across labelled columns without truncation. All untrusted text is written as literal strings, with no formulas or hyperlinks. Active summaries exclude voids; detail retains them.

The download uses the XLSX MIME type, a safe attachment filename, private/no-store caching and explicit errors. Two builders are allowed per Node runtime. Complete responses above 4 MiB fail explicitly rather than returning partial history; larger future histories require a private download-storage path. Export has no email, business write or uploaded-workbook parsing endpoint.

Dependency: pinned [ExcelJS 4.4.0](https://github.com/exceljs/exceljs/releases/tag/v4.4.0), MIT licence and published integrity checked against the [official registry](https://registry.npmjs.org/exceljs/4.4.0). The worktree owns its dependency directory; the primary checkout's directory is unchanged. A nested lock keeps every original dependency entry/version. Scoped, compatible patches pin only the new tree's minimatch 3.x to 3.1.4 and its brace-expansion to 1.1.21; the tree's minimatch 5.x remains on its own compatible major. Registry metadata and a frozen-lock install check confirm reproducibility.

Production dependency audit: baseline 20 advisories, reviewed tree 21. High and critical counts remain unchanged at 12 and 1. The added inherited ExcelJS advisory follows UUID's v3/v5/v6 buffer API; the library's relevant generated-ID code uses v4. This writer uses the in-memory JSZip path, with no user-supplied filenames, filesystem globbing or archive imports. Existing project advisories are not silently fixed through unrelated framework upgrades; this is not a clean whole-project security bill.

Evidence is retained privately for the two-ID SQL boundary, all-period history, 501+ records, exact high-precision values, true empty Emmanuel activity, actual XLSX round-trip, literal formula-looking text, long Unicode, binary API download, suspended/foreign denials, bounded concurrency, failures, account-switch cancellation and real responsive export controls. Synthetic records exist only in isolated tests. Full production restore/migration/concurrency rehearsal and final release review remain Task 8.
